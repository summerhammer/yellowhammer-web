Prepare one [Project](/reference/statuses-and-glossary#project), check its local tools and service access, then run its first [Night](/reference/statuses-and-glossary#night) and review the results in Linear and GitHub. Acme Checkout is an illustrative product used below.

## Before you begin

Check [Requirements](/start/requirements). Use an Apple Silicon Mac running macOS 26 or later, local repository and specification checkouts, Orca ADE, Linear, GitHub, and an authenticated supported coding agent CLI.

## 1. Prepare the machine

Open **Settings → Agent CLIs**, declare the installed CLI, and configure a route naming it in **Base Routing Table**. Run **Probe Now** and resolve any failure before relying on unattended dispatch. Confirm setup can find Orca. Follow [Connect Orca and agent CLIs](/setup/connect-orca-and-agent-clis).

If you want terminal access to `yh`, choose **Install…** in **Settings → General → Command Line Tool**. Scheduled jobs use the bundled executable and do not depend on this optional terminal link.

## 2. Add the Project

Open **Add Project…** and complete its steps:

1. Name the Project, for example Acme Checkout, and inspect its permanent ID.
2. Connect Linear through local or remote admin approval. Choose your Operator identity and the Linear project.
3. Add working repositories with their Repo Roles and Check commands. Review proposed Repo Dependencies.
4. Select a GitHub connection and inspect the repository access report.
5. Select the specification source and review the per-Project Bounds.
6. Open **Schedule** and set the Night window. Choose **Not now** for scheduled jobs while you review setup, then choose **Add Project** and confirm the ID.

Read the run log and choose **Done** after success. The [setup guide](/setup/add-project-and-repositories) explains each decision and setup failure.

## 3. Check the Project before unattended work

Open the Project in Settings and confirm its repositories, Linear project, specification source, and connections. Follow [Rehearse before scheduling](/run/rehearse-before-scheduling) to configure and run a rehearsal when you want to exercise the flow first. A rehearsal needs a separate declared rehearsal Linear project and Journal; it writes to Linear but never dispatches an agent, pushes, or opens a pull request.

## 4. Start work and configure the schedule

Select the Project and choose **Start Author** in the toolbar to start its author Act. This starts authoring; it does not itself run the entire author/build/land sequence. Follow [Configure the schedule](/run/configure-the-schedule) to install or refresh the scheduled jobs that run those Acts automatically.

Keep the Mac available during its Night window. The jobs can run with Yellowhammer quit. Watch progress in the Project's [Pulse and Inspector](/review/understand-pulse-and-inspector), and respond to questions in Linear when needed.

## 5. Review the result

Read the [Night Summary](/review/read-the-night-summary), inspect the Features and Work Cards in Linear, and follow any pull request links to GitHub. A Night can progress through several Features within its configured limits. Review the evidence and any incomplete or blocked work before deciding what to merge.

## Confirm it worked

The Project is visible in Yellowhammer, its authored work is visible in the intended Linear project, and the Night Summary explains the outcome. When work reaches publication, GitHub has pull requests for your review. A blocked or incomplete Night can still produce useful progress; use the recorded reason to decide your next action.
