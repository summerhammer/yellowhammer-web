Set up one [Project](/reference/statuses-and-glossary#project) by connecting its services, choosing its local repositories and specification, and reviewing the limits and schedule before unattended work.

## Recommended reading order

Prepare the machine-wide tools first, then complete the Project-specific choices in **Add Project…**. If setup shows **Before You Start**, follow its Settings link to declare a CLI and configure a base route.

## What a Project contains

The Add Project wizard covers **Project**, **Board**, **Repos**, **Code Hosting**, **Spec Source**, **Bounds**, and **Schedule** (the last pane is titled **Scheduled jobs**). Its sidebar shows each step's summary and readiness. You can revisit steps before confirming **Add Project**.

Workspace connections and Operator identity choices save independently of the Project draft. Cancelling the sheet does not disconnect a workspace you just connected. The Project's permanent ID is confirmed when you add it.

## Before leaving setup

Check that the selected Linear project belongs to the product, every working repository is included, the GitHub check covers those repositories, and the specification source is correct. Choose **Not now** for scheduled jobs if you want to inspect and rehearse the setup first.
